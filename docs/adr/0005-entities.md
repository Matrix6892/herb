# 0005. Сущности модели данных
status: accepted
date: 2026-09-26

Источник: спецификация фазы 1, §4.2 (`docs/spec-phase-1.md`). Решение
принято владельцем; ADR фиксирует его и место реализации.

## Решение
Сущности спецификации реализованы как типы `catalog-core` (`Substance`, `Form`, `Product`, `Label`, `LabelLine`, `Category`) и записи `catalog-store` (`PriceSnapshot`, `RatingSnapshot`, `ClickEvent`, `ErrorReport`). Строка этикетки хранит заявленное (`Declared::SaltMass | ElementalMass | Iu`) отдельно от посчитанного (`LineDose`). Смена формулы — новая версия `Label` с `effective_from`.

## Почему (предпосылки)
Пользователь видит источник каждого числа; уверенность хранится по каждой строке.

## Для чего (будущее)
Справочник форм фазы 2 и разделение отзывов до и после смены формулы в фазе 3.

## Границы
Нули и заглушки вместо неизвестного запрещены (И7): отсутствие цены — NULL, строка с `unknown` исключает товар.

## Что проверить, если предпосылка не подтвердится
Если понадобится поле, которого нет в спецификации, — ADR со статусом `assumed` (пример: ADR 0014).

Реализация: `crates/catalog-core/src/{reference,label,product}.rs`, `crates/catalog-store/src/records.rs`.
