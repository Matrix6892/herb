# 0008. Рейтинг с поправкой и ветки A/B
status: accepted
date: 2026-09-26

Источник: спецификация фазы 1, §5.3, §5.4 (`docs/spec-phase-1.md`). Решение
принято владельцем; ADR фиксирует его и место реализации.

## Решение
`R_b = (n·R + C·m)/(n + C)`, где `m` — среднее по товарам категории с известным рейтингом, `C` — медиана числа отзывов. Ветка задаётся в `config/vitrina.toml` (`rating_branch`), по умолчанию B (О2). В ветке B рейтинги не пишутся в базу и не показываются, пресеты `cheapest_per_unit` и `cheapest_verified`.

## Почему (предпосылки)
Доверие: 5,0 на 8 отзывах не должна обгонять 4,8 на 40 000; показ рейтинга зависит от разрешения iHerb.

## Для чего (будущее)
Фаза 2 использует те же `R_b` для Парето-фронта.

## Границы
Без разрешения рейтинг не показывается нигде (тест `branch_b_shows_no_ratings_anywhere`).

## Что проверить, если предпосылка не подтвердится
Когда О2 будет решён, меняется одна строка конфигурации; код поддерживает обе ветки через `Option`.

Реализация: `crates/catalog-core/src/rating.rs`, `scoring.rs`, `config/vitrina.toml`.
