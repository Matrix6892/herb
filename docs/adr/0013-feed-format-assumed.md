# 0013. Формат фида до получения образца
status: assumed
date: 2026-09-26

## Решение
Пока сеть не дала образец фида (О3), `feed-ingest` читает CSV или TSV (в том
числе gzip) с колонками общего вида каталогов Impact. Заголовки сравниваются
без учёта регистра, пробелов, `_` и `-`; для каждой колонки есть список
синонимов (`crates/feed-ingest/src/columns.rs`):

| Поле | Колонки | Обязательна |
| --- | --- | --- |
| страница товара | `ProductUrl`, `OriginalUrl`, … или параметр `u` трекинговой ссылки | одна из двух ссылок |
| трекинговая ссылка | `Url`, `TrackingUrl`, … | одна из двух ссылок |
| название | `Name`, `ProductName`, `Title` | да |
| бренд | `Manufacturer`, `Brand` | нет |
| цена | `CurrentPrice`, `SalePrice`, `Price` | да |
| валюта | `Currency` | нет; если есть, только USD |
| наличие | `StockAvailability`, `Availability`, `InStock` | да |
| категория | `Category`, `SubCategory` | да |
| цена только в корзине | `PriceHiddenUntilCart`, … | нет, по умолчанию `false` |
| рейтинг, число отзывов | `Rating`, `ReviewCount`, … | нет; только ветка A |

`iherb_id` и `slug` берутся из пути `/pr/<slug>/<id>` страницы товара; эта
ссылка только разбирается и никогда не запрашивается (И1). Если в фиде есть
колонка id и она расходится с путём, строка отвергается. Нулевая или пустая
цена хранится как отсутствие цены (И7). Неизвестное значение наличия, не-USD
валюта, дубль id, путь не вида `/pr/<slug>/<id>`, трекинговая ссылка не https
или ведущая прямо на iherb.com — строка отвергается с причиной, которая
печатается в отчёте `vitrina ingest`. Товар попадает в категорию, если один
из сегментов пути категории (`Supplements > Minerals > Magnesium`) совпадает
со значением `feed_match` категории целиком. Фид без обязательных колонок или
без единой строки в известной категории считается непригодным: код 2, снимок
не пишется.

## Почему (предпосылки)
Спецификация велит писать по образцу общего формата Impact (дефолт О3). Точных
имён колонок фида iHerb у нас нет, поэтому набор синонимов, а не одно имя.

## Для чего (будущее)
Когда придёт настоящий фид, меняется только `columns.rs` и образец в
`data/fixtures/feed/`; остальная система видит `catalog_store::FeedDay`.

## Границы
`feed-ingest` никогда не обращается к iherb.com, в том числе по редиректу.
Цена в другой валюте не конвертируется.

## Что проверить, если предпосылка не подтвердится
- Есть ли в фиде ссылка на страницу товара или только трекинговая ссылка без
  параметра `u`: если нет ни того, ни другого, нужен другой источник `slug`.
- Числовой ли `CatalogItemId` и совпадает ли он с id в пути iHerb.
- Значения категорий: подходит ли `feed_match = ["Magnesium"]`.
- Разрешено ли использовать изображения (сейчас не используются).
