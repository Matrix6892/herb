# 0016. Как измеряется бюджет производительности и как отдаются пресеты
status: assumed
date: 2026-09-26

## Решение
1. Стили встраиваются в `<style>` каждой страницы при сборке (с простой
   минификацией), чтобы у первой отрисовки не было блокирующих запросов.
   Бюджет CSS 30 КБ проверяется на исходном `site/static/site.css`.
2. HTML страницы категории до 60 КБ считается в сжатом gzip виде (так он
   передаётся по сети), JS до 10 КБ — в исходном виде.
3. Три пресета не отрисовываются тремя полными списками. Карточки товаров
   отрисованы один раз в порядке пресета по умолчанию; порядки остальных
   пресетов — списки id в атрибутах `data-o-<preset>` у `<ol>`. Скрипт
   переставляет карточки и перенумеровывает. Карточки, которых нет в пресете
   по умолчанию, выводятся с `hidden`.
4. Статический хостинг отдаёт `/c/magnesium` из `c/magnesium.html` (так
   работает Cloudflare Pages); `tools/serve-site.py` повторяет это локально.
5. Lighthouse в CI — профиль мобильного телефона по умолчанию (Slow 4G, 4×
   CPU, строже 4G из спецификации), медиана трёх прогонов, утверждение
   `first-contentful-paint ≤ 1000 мс`. На фикстуре: 0,7–1,0 с, все категории
   Lighthouse 1,0.

## Почему (предпосылки)
Спецификация требует и «без блокирующих запросов», и отдельный CSS-файл;
встраивание выполняет оба условия. При 50–150 товарах три полных списка
заняли бы больше 60 КБ даже при сжатии, а один набор карточек с порядками
укладывается.

## Для чего (будущее)
Фильтры фазы 2 в адресе используют тот же механизм порядков.

## Границы
Страница остаётся полной без JavaScript (пресет по умолчанию).

## Что проверить, если предпосылка не подтвердится
Если бюджет 60 КБ задуман для несжатого HTML, на 150 товарах его не хватит:
тогда страница категории показывает первые N карточек и ссылку на полный
список.
