# 0017. Уточнения расчётов, не описанные в спецификации
status: assumed
date: 2026-09-26

## Решение
- «Равенство в пределах 1e-9» (§5.5) реализовано как равенство после
  округления до сетки 1e-9: сравнение с эпсилоном не транзитивно и ломает
  сортировку, сетка даёт полный порядок и совпадает с ним на практике.
- Если все рейтинги в выборке равны (не только при одном товаре),
  `q_rating = 100` для всех — по аналогии с правилом `P_max = P_min`.
- `fair_rating`: по `R_b` убыв., затем `P_unit` возр., затем `iherb_id`.
- Строка этикетки с `confidence = unknown` любого вещества исключает товар
  (§4.2); строки вещества категории должны быть `verified`, строки других
  веществ могут быть `recognized`.
- Товар без наличия (`in_stock = false`) остаётся в пресетах с пометкой «Out
  of stock»: в §5.2 это не названо причиной исключения.
- Фразы «почему здесь» в порядке: цена к медиане категории (в том числе
  «дороже медианы» — честно, а не только «дешевле»), рейтинг (ветка A),
  смена формулы, знак теста; не больше трёх. Медиана — по товарам с `P_unit`.
- Товар, которого нет в сегодняшнем фиде, получает статус `delisted`,
  страницу с причиной и без кнопки покупки.
- Отображение: цена за единицу с тремя знаками доллара, массы с точностью до
  микрограмма, знак `≈` у строки, чья точная доля не целая.

## Почему (предпосылки)
Спецификация не определяет эти случаи, а код обязан их обработать.

## Для чего (будущее)
Парето-фронт фазы 2 использует те же оценки и тот же порядок.

## Границы
Ни одно уточнение не вводит в формулы данные о комиссии (И2).

## Что проверить, если предпосылка не подтвердится
Каждый пункт меняется локально в `catalog-core::scoring` или
`catalog-core::category`; тесты ядра и снимки HTML покажут последствия.
