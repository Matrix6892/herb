# 0020. Файл оценки категории — единственный источник чисел для скриптов
status: assumed
date: 2026-09-26

## Решение
`site-gen` при каждой сборке пишет рядом со страницей категории файл
`c/<slug>.json` (схема `vitrina.category-evaluation/1`). В нём то, что
посчитал `catalog-core` для этой категории на этот снимок:

- версия правил (`catalog_core::RULES_VERSION`) и снимок: дата, время и
  SHA-256 фида;
- порядок каждого пресета ветки; причина, если пресет пуст;
- разрыв №1 и №2 на шкале пресета (`balance_points`, `price_ratio`,
  `rating_diff`); его нет, если в пресете меньше двух товаров;
- для каждого товара: цена за единицу (значение и текст сайта), отношение
  к медиане, места во всех пресетах, количество на порцию и на упаковку,
  рейтинг и скорректированный рейтинг (только ветка A), `q_price`,
  `q_rating`, `s`, слабая сторона и пороги области «ranks above»
  (`BalanceNorm::price_at`, `rating_at`), строки этикетки, причина
  исключения;
- медиана, разброс цен и диапазоны нормировки с признаком, есть ли разброс.

Нечисловые значения записываются как `null`, отсутствующие — не
записываются. Скрипт (сайт, прототип, будущая карта) позиционирует и
форматирует, но не ранжирует и не считает баллы.

Прототип `design/prototypes/magnesium-ranking.html` собирается скриптом
`tools/build-prototype.py` из `magnesium-ranking.src.html` и файлов
`design/prototypes/cases/*.json`. Эти файлы пишет и сверяет тест
`site-gen --test evaluation`: фикстура в ветках A и B и крайние случаи
(0 и 1 сравнимый товар, товар без рейтинга, одинаковые цены, одинаковые
рейтинги, ветка B без знаков на этикетках). Браузерный тест
`design/prototypes/tests/states.mjs` открывает прототип на каждом случае.

## Почему (предпосылки)
Ревью базы `233b748` (PR-05 пакета передачи): прототип пересчитывал `qp`,
`qr`, `s` в JavaScript по округлённым полям, без защиты от вырожденных
диапазонов, и обращался к несуществующему №2. Воспроизведено в браузере:
один товар и пустой пресет — `TypeError`, одинаковые цены — `NaN` на
странице. Кроме того, из-за округления прототип показывал разрыв 5,1 балла
вместо 2,99 и слабую сторону 49 вместо 46.

Спецификация не описывает машиночитаемый выход сборки. Файл — допущение
реализации: публичный, без личных данных, та же информация, что уже на
страницах.

## Для чего (будущее)
Карта на рабочем сайте, страница товара и расширение (фаза 4) читают тот же
файл. Динамический пользовательский контекст (J1, решение D03 пакета) этим
файлом не покрывается: для него нужен вызов того же `catalog-core` (WASM
или сервер) — отдельное решение.

## Границы
Файл не содержит рейтингов в ветке B. Он не заменяет HTML: страница
полна без скрипта. Бюджет JS (10 КБ) не затронут: файл не является
скриптом.

## Что проверить, если предпосылка не подтвердится
Если хостинг не отдаёт `.json` с правильным типом или файл окажется
лишним для рабочего сайта, сборка может писать его только в каталог
артефактов разработки; тест `site-gen --test evaluation` и прототип от этого
не меняются.
